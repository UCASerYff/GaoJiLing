# 搞机灵 V1.16 for Windows

面向 Windows 10/11 x64。桌面窗口显示 V1.16，关于页显示构建 5，命令行显示 1.16+5。使用按用户安装的 x64 MSI，无需管理员权限。安装包未进行 Authenticode 签名。

## 安装与运行

从发布页下载 `GaoJiLing-1.16+5-Windows-x64.msi` 和同名 `.sha256`，用 `Get-FileHash -Algorithm SHA256` 核对后运行 MSI。升级前先从通知区域退出旧版。若旧版使用自定义安装目录，请继续用 `INSTALLDIR` 指定原目录。从开始菜单打开搞机灵。主窗口优先使用本机 WebView2 Runtime，系统未提供该组件时使用独立的 Microsoft Edge 应用窗口或系统浏览器。

构建 5 从现有书法图标生成 16 至 256 像素的 20 档原生资源。窗口和通知区域各按所在显示器的 DPI 选择图标。Windows 重新创建任务栏时，搞机灵会按当前 DPI 重新登记托盘图标。开始菜单快捷方式与原生窗口使用相同的应用标识。独立 Edge 后备窗口也使用这些资源，任务栏分组由浏览器管理。

构建 4 修复了原生 WebView2 窗口进程启动时的缺失导入。此前故障会在主窗口启动或从通知区域恢复时触发 PyInstaller 异常窗口。Edge 后备窗口刚打开就关闭时，后续的托盘恢复请求会等到窗口可以打开。

关闭主窗口后，搞机灵在 Windows 通知区域保留一个图标，并继续采样和记录任务。单击图标或右键选择「打开 搞机灵」恢复主窗口。Windows 可能把图标放在通知区域的溢出菜单。

右键选择「退出」结束程序。正在录制任务时，可以选择结束并保存，或取消退出并继续记录。已有操作正在提交时，等操作完成再退出。退出后通知区域图标、全局快捷键、唤起条、浮窗及本机监控服务一并关闭。系统浏览器后备模式的标签页属于浏览器，应用只关闭本机服务。

点击、悬停桌面唤起条，或按 Ctrl+Alt+G（可改为 Ctrl+Alt+M）可打开浮窗。拖动唤起条或浮窗顶部的 CPU 区域可以移动位置。鼠标移出、外部点击或按 Esc 可收起。Ctrl+, 打开设置，Ctrl+Shift+E 打开数据设置。全局快捷键冲突、通知投递和登录启动状态由 Windows 报告。

旧 MSI 的卸载流程会移除旧登录快捷方式。如果之前开启了登录启动，升级后可在模块设置里核对 Windows 登记状态并重新开启。

## 工作区

| 页面 | Windows 操作 |
| --- | --- |
| 概览 | 四项核心读数、共用时间轴的 CPU 与内存趋势、活跃应用排行和设备状态。可进入维护页核对指标来源。 |
| 应用 | 搜索应用或进程，按全机 CPU 或工作集排序，并可打开任务管理器。第一次缺少 CPU 基线的读数显示不可用。 |
| 回看 | 10 分钟、1 小时、24 小时范围，按异常事件定位并导出。将焦点移至图表，可用方向键查看实际采样点。采样空档留白。 |
| 任务 | 同一页开始和结束记录，查看实时计时及逐项 CSV。勾选两次已完成的记录，比较耗时、CPU 均值与峰值、内存峰值、采样趋势和可用的进程占用排行。上次运行中断时收尾到最后一次实际采样。 |
| 网络 | 手动检查本机连接、网关、输入域名的 DNS 和 HTTPS。 |
| 清理 | 扫描可验证归属的过期应用或开发工具缓存及轮转日志，逐项确认移入 Windows 回收站，按批恢复。内存区可请求收缩本进程工作集。 |
| 存储 | 开发环境和所选目录的元数据树、比例磁盘地图、钻取、排除、搜索排序、同范围完整历史和 CSV。重复文件与普通 NTFS 镜像在各自页签单独确认内容读取。 |
| 维护 | 按指标核对采样时间、来源、不可用或过期原因，设置电池读数阈值提醒。 |
| 应用管理 | 查看已安装应用，通过 Windows 设置走厂商卸载。对可验证的独立程序目录单独复核、移入回收站并按批尝试恢复。 |
| 交接 | 本地导入 `.gaoaction` 目录，复核来源声明和引用，确认后进入对应业务。只能用实际分析或移动回执生成结果。 |

Windows 通知由系统通知设置及专注模式决定是否显示。登录启动在正式安装并由本人启用后登记。监控和窗口通信只使用本机回环，联网诊断按需连接指定主机。

## 平台范围

- 进程 CPU 以整机总容量为 100%。Windows 物理内存压力来自系统内存负载估算，磁盘、GPU 与热区依赖本机性能计数器。固件或权限未提供的温度、功耗、硬件健康和风扇转速显示具体缺项。电池和散热是只读监测。
- Windows 的清理路径采用本系统的已知缓存和轮转日志规则。日志至少保留 30 天，缓存至少 7 天。路径、归属或运行状态无法核验时跳过。回收站中的项目仍占用磁盘空间，恢复会避开原位置的新内容。
- 卷枚举要求可证实的内置物理设备拓扑，通过 Windows 提供的盘符和公开元数据工作。系统拒绝设备映射或归属不明时显示原因。普通 NTFS 镜像支持已核验的父路径、搜索、报告和普通默认流提取。压缩、加密、稀疏、命名流和不支持的扩展记录无法提取。目录观察有上限。提取仅写入新文件。
- 统一确认第三方应用未保存状态、强制收缩系统文件缓存、充电限制和风扇写控制没有启用。Windows 系统安装应用使用 Windows 设置及厂商的权限和卸载流程。Windows 交接通过显式导入和导出开展。
- 文件扫描、内容分析和卷读取在系统调用之间检查取消与预算。已发出的调用可能需等待 Windows 返回。

## 资料与兼容性

默认资料目录仍为 `%APPDATA%\GaoSeries\GaoJiLing`。安装和卸载只处理程序，资料留给本机用户。数据库使用既有的 `monitor.sqlite` 表和时间格式，`panel.json` 保留已保存的横纵位置。清理、重复文件、卸载和交接的日志及待恢复项目属于业务资料。

如果正在运行旧的便携版，先退出旧版，再从开始菜单打开新版。两版共享默认资料目录，日常应由一个实例使用。

历史通常每约 10 秒保存一次。历史和事件默认保留 7 天，可设置 1–30 天。超过 24 小时的采样按分钟保留实际数据点。任务独立保留。设置内可按时间和类别导出 CSV，或导出带 SHA-256 完整性检查的监控 JSON。恢复完整 JSON 会替换所选资料，不自动备份被替换的内容。资料和导出可能含本机路径及名称，应留在本机。

任务对比沿用原任务汇总和采样频率。正常结束任务或从托盘确认保存退出时，最多为最近 48 个任务保留会话明细，每次至多 120 个真实趋势点和一次最多 8 组的进程排行。排行使用任务内整机 CPU 最高且有完整进程 CPU 基线的采样，显示该次工作集。更早的任务和应用中断后恢复的任务仍能读回已有汇总，有保留历史时可查看任务时段内的系统趋势。进程占用只取可归属到本会话的明细。

从 Windows 构建 4 起，应用在原 SQLite 文件中按需新增一张关联表，旧记录无需改写。完整 JSON 沿用原格式，可随任务导出和恢复明细。

## 构建与检查

使用干净的 x64 CPython 3.12 环境。在 `windows` 下执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Python <虚拟环境中的 python.exe>
```

脚本运行测试并在 `windows/dist` 生成安装包和 SHA-256 文件。隔离冒烟用 `smoke-installed.ps1 -Package <MSI 路径> -Python <python.exe>`。传入 `-PreviousPackage <构建 4 的 MSI 路径>` 可核对 Windows Installer 从旧构建升级。冒烟校验原包摘要，使用独立的 MSI 标识与合成资料执行安装、运行和卸载。

用 `<python.exe> smoke-desktop.py --exe <构建目录中的 GaoJiLing.exe>` 在独立的非活动 Windows 桌面验证通知区域回调、窗口和退出流程。加 `--require-webview2` 可要求原生 WebView2 窗口和实际页面内容都通过。用 `<python.exe> tests/smoke_tray_shell.py build/package/AppIcon.ico` 在运行 Explorer 的 Windows 会话验证实际的 Shell 图标登记、重新登记和移除。测试使用自己的隐藏窗口和图标，不修改通知区域偏好。

CI 会比较冻结程序内的 ICO 和原生图标资源，并向 Windows 请求 100%、125%、150%、175%、200% 的尺寸。向桌面冒烟传入 `--expected-icon build/package/AppIcon.ico` 可核对窗口实际选中的 HICON。加 `--icon-artifacts <截图目录>` 可保存 WebView2「应用」页在五档浏览器缩放下的截图。

运行 `GaoJiLing-cli.exe --version` 查看版本。用 `--inspect` 查看资料条数，或用 `--serve --no-browser --data-dir <隔离目录> --port <本机端口>` 进行独立调试。

## 构建 4 验收

- 干净的 x64 CPython 3.12 环境通过 62 项 Windows 回归。
- 在 Windows 11 使用同一冻结候选实际运行原生 WebView2。首次打开、关闭后通过通知区域选择和菜单恢复，以及设置窗口均核对了独立窗口和已加载页面。确认退出与取消退出、窗口和进程清理、全局热键和回环端口通过隔离回归。
- 在独立测试中使 WebView2 运行时路径不可用，核对了 Edge 独立窗口后备的打开、快速闭窗后的通知区域恢复和退出。
- 从任务页选择两条合成记录，核对对比差值、同刻度趋势、键盘读图、会话内进程排行和旧任务缺少采样的情况。在同一原生窗口核对浅色和 150% 深色窄窗。
- 在真实 Windows Installer 中将隔离安装从构建 3 原地升级至构建 4，读回旧任务、设置和浮窗位置，比较旧任务与新采样，再验证退出和卸载保留资料。

## 构建 3 验收

- 通过 56 项 Windows 回归。在 Windows 11 用真实 Windows Installer 验证隔离的构建 2 到构建 3 升级。新版读回旧任务、主题、保留期、快捷键和浮窗位置，能写入新任务，卸载保留资料。
- 在非活动桌面运行打包后的应用，通过 Windows 消息核对闭窗后的采样和记录、托盘选择和菜单恢复、第二次启动转发、浮窗热键、取消退出和保存退出。退出后进程、应用窗口和回环端口关闭，全局快捷键可以重新登记。命令行无桌面入口时不创建通知区域窗口。
- 使用同一应用图标在真实 Shell 中验证登记、删除、重新登记和最终移除。在非活动桌面向实际应用发送 `TaskbarCreated`，核对消息路径。现场未重启 Explorer 或操作真实通知区域。独立窗口验收走 Edge 后备路径，原生 WebView2 和 Windows 10 实机未在本轮复测。

## 构建 2 验收

- 干净的 x64 CPython 下通过 50 项测试。覆盖监控历史和任务、权限失败、清理与恢复、重复文件、卷镜像和外部交接。
- 在 Windows 11 使用真实 Windows Installer 验证私有标识下从 1.16+1 升级至 1.16+2、启动两个 x64 程序和卸载。升级前后核对隔离数据库与浮窗位置。新构建读回旧任务、深色主题、14 天保留期和 Ctrl+Alt+M 设置，写入新任务后正常退出，卸载保留资料。
